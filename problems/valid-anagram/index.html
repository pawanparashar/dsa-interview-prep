#2 — Valid Anagram

Arrays & Hashing LeetCode 242 NeetCode "Valid Anagram" Easy
Download one-pager (PDF) ↓

Problem

Given two strings s and t, return true if the two strings are anagrams of each other, otherwise return false. An anagram is a string that contains the exact same characters as another string, but the order of the characters can be different.

s = "racecar", t = "carrace" → true
s = "jar", t = "jam" → false

Watch the walkthrough

Core idea

Goal
Determine whether two strings are anagrams of each other.

Key insight
Two strings are anagrams exactly when they contain the same characters the same number of times — order doesn't matter, so the problem reduces to comparing character frequency counts instead of comparing the strings directly.

Trigger phrase: “Same letters, different order?” → reach for a character frequency count (Hash Map).

Step through it

Walkthrough

Two strings are anagrams exactly when every character appears the same number of times in both — order doesn't matter, so this calls for frequency counts rather than a position-by-position comparison.

First check: if the lengths differ, the strings can't be anagrams, so return False immediately without doing any counting — a cheap short-circuit.

Build two frequency dictionaries in a single pass over both strings together (same index ch), incrementing each character's count with .get(char, 0) + 1 so a character seen for the first time defaults to 0 instead of raising a KeyError.

Then compare: walk every key in counterS and check it has the same count in counterT (again using .get, so a character missing from t just reads as 0 and fails the comparison instead of throwing). If every count lines up, the strings are anagrams.

Because s and t only contain lowercase English letters (per the problem's constraints), each dictionary never holds more than 26 keys — so despite looking like O(n) extra space, it's effectively O(1).

Optimal solution

Data structure: Two Hash Maps (Python dict) tracking character counts

  1. If s and t have different lengths, they can't be anagrams — return False immediately.
  2. Walk both strings together in one pass, building counterS and counterT with dict.get(char, 0) + 1.
  3. For every character in counterS, compare its count against counterT.get(char, 0); any mismatch means the strings aren't anagrams — return False.
  4. If every character's count matches, return True.
O(n + m)Time
O(1)Space

Code

class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        counterS, counterT = {}, {}
        if len(s) != len(t):
            return False

        for ch in range(len(s)):
            counterS[s[ch]] = 1 + counterS.get(s[ch], 0)
            counterT[t[ch]] = 1 + counterT.get(t[ch], 0)

        for c in counterS:
            if counterS[c] != counterT.get(c, 0):
                return False

        return True

Other ways to solve it

Pythonic one-liner — collections.Counter

Same O(n) idea, but lets Counter do the counting and the comparison in one expression. Easiest to write correctly under interview pressure, and reads cleanly — the main trade-off is it's a library call instead of showing your own counting logic, so some interviewers may ask you to implement it by hand anyway (the primary solution above).

from collections import Counter

class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        if len(s) != len(t):
            return False
        return Counter(s) == Counter(t)
O(n + m)Time
O(1)Space

Sorting

The simplest to reason about: two strings are anagrams exactly when sorting both produces the same sequence. Easier to explain out loud and needs no extra data structure, but it's slower — O(n log n) instead of O(n) — so it's a good fallback if you blank on the hash map approach, not the first choice.

class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        return sorted(s) == sorted(t)
O(n log n)Time
O(n)Space

Edge cases to consider

  • Different lengths → return False immediately, no counting needed
  • s and t are identical strings → trivially anagrams
  • All identical characters, e.g. "aaa" vs "aaa" → true
  • Input is lowercase-only per constraints — mixed case or Unicode input would need normalizing first
