#5 — Top K Frequent Elements

Arrays & Hashing LeetCode 347 NeetCode "Top K Elements in List" Medium
Download one-pager (PDF) ↓

Problem

Given an integer array nums and an integer k, return the k most frequent elements within the array. The test cases are generated such that the answer is always unique. You may return the output in any order.

nums = [1,2,2,3,3,3], k = 2 → [2,3]
nums = [7,7], k = 1 → [7]

Watch the walkthrough

Core idea

Goal
Return the k values that appear most often in an array, without sorting the whole frequency distribution.

Key insight
A value's frequency can never exceed the length of the array, so instead of sorting all (value, frequency) pairs by frequency — O(n log n) — bucket each value directly into an index equal to its frequency count. Reading the buckets from the highest index down then visits values in descending frequency order for free, in O(n) overall.

Trigger phrase: “Top / most frequent k” with no need for full sorted order → bucket sort by frequency (Hash Map + array of buckets), not a heap or a full sort.

Step through it

Walk the algorithm one step at a time — forward, back, or press play.

Walkthrough

The naive approach is to count frequencies, then sort the (value, frequency) pairs to pull off the top k — but sorting costs O(n log n) when the counting itself only needed O(n). Bucket sort avoids the sort entirely by exploiting a hard limit: no value can appear more than len(nums) times.

First pass: build a frequency hash map the normal way, incrementing freq[num] for every number in nums.

Second pass: instead of sorting by frequency, place each value directly into a bucket array at the index equal to its own frequency — res[value].append(key). Because frequency is bounded by the array length, res only needs len(nums) + 1 slots (index 0 through len(nums)) to hold every possible frequency.

This bucketing step is the key trick: values that share a frequency automatically land in the same bucket, and the bucket array is naturally ordered from low frequency (index 0) to high frequency (last index) with no comparisons needed.

Final pass: walk the buckets from the highest index down to 0. The first non-empty buckets encountered hold the most frequent values, so appending their contents to the output — stopping once it reaches k elements — directly yields the k most frequent values without ever sorting anything.

Optimal solution

Data structure: Hash Map for counts, plus a bucket array of size len(nums) + 1 indexed by frequency

  1. Count every value's frequency into a hash map freq with a single pass over nums.
  2. Create a bucket array res of size len(nums) + 1 — a value can appear at most len(nums) times, so every possible frequency has a slot.
  3. For each (key, value) pair in freq (value is the frequency), append key into res[value] — this groups all values that share the same frequency into the same bucket.
  4. Walk res in reverse (highest frequency first). Any non-empty bucket holds values of that frequency; append them to the output until it has k elements.
  5. Return the collected output.
O(n)Time
O(n)Space

Code

class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        freq = defaultdict(int)
        for num in nums:
            freq[num] += 1

        res = [0] * (len(nums)+1)

        for key,value in freq.items():
            if res[value] == 0:
                res[value] = [key]
            else:
                res[value].append(key)

        out = []
        for item in reversed(res):
            if item != 0 and len(out) < k:
                for i in item:
                    out.append(i)

        return out

Other ways to solve it

Heap (heapq.nlargest)

Count frequencies the same way, then let a heap pull the k largest in O(n log k) instead of O(n). More idiomatic Python and easy to justify, but asymptotically worse than bucket sort for this problem since frequency is bounded — mention bucket sort as the optimal approach, heap as the natural fallback.

import heapq

class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        freq = defaultdict(int)
        for num in nums:
            freq[num] += 1
        return heapq.nlargest(k, freq.keys(), key=freq.get)
O(n log k)Time
O(n)Space

Counter.most_common

Python's Counter does the counting and gives a built-in most_common(k). Shortest to write under time pressure, but it's a library call hiding the same O(n log n) sort under the hood (or a heap, depending on implementation) — good as a one-liner fallback, not a substitute for explaining the bucket-sort trick.

from collections import Counter

class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        return [key for key, _ in Counter(nums).most_common(k)]
O(n log n)Time
O(n)Space

Tips to remember this pattern

Mental shortcut — “Frequency can't exceed array length → bucket by frequency, read buckets top-down.”

"Frequencies are bounded by the array length, so I bucket values by frequency into a fixed-size array instead of sorting (value, frequency) pairs — that turns an O(n log n) sort into an O(n) counting pass plus an O(n) bucket scan."

Edge cases to consider

  • k equals the number of distinct values → every bucket with any value is collected, output has exactly k elements
  • All elements are identical, e.g. [7,7] → one bucket at the max index holding a single key, k = 1 returns that key
  • Every element is unique → every value sits in bucket index 1; any k of them is a valid answer since the problem guarantees a unique result set
  • Multiple keys landing in the same bucket when k falls in the middle of that bucket: the reference solution's outer check (len(out) < k) is tested once per bucket, so it can append an entire tied bucket even if that slightly overshoots k — worth mentioning as a trade-off versus trimming to exactly k inside the inner loop
  • Empty nums array → freq and buckets stay empty, output is empty (k would be 0 in that case per the problem's constraints)
