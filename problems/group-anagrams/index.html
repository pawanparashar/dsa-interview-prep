#4 — Group Anagrams

Arrays & Hashing LeetCode 49 NeetCode "Group Anagrams" Medium
Download one-pager (PDF) ↓

Problem

Given an array of strings strs, group the anagrams together. You can return the answer in any order. An anagram is a string that contains the exact same characters as another string, but the order of the characters can be different.

strs = ["eat","tea","tan","ate","nat","bat"] → [["bat"],["nat","tan"],["ate","eat","tea"]]
strs = ["x"] → [["x"]]

Watch the walkthrough

Core idea

Goal
Partition a list of strings into groups where every string in a group is an anagram of every other string in that group.

Key insight
Anagrams always produce the same letter-frequency signature, so instead of comparing every pair of strings (O(n²) work), compute one canonical "fingerprint" per string and use it as a hash map key — strings with the same fingerprint land in the same bucket automatically.

Trigger phrase: “Group things that are the same letters rearranged” → build a frequency-count signature and bucket by it (Hash Map).

Walkthrough

The brute-force instinct is to compare every string against every other string to check if they're anagrams — but that's O(n²) comparisons, and each comparison itself costs time. The faster approach flips the problem: instead of comparing strings to each other, give every string a canonical "fingerprint" that's identical for all of its anagrams, then just group by that fingerprint in one pass.

The fingerprint used here is a 26-element array counting how many times each lowercase letter appears in the string — count[ord(c) - ord('a')] += 1 maps 'a' → index 0, 'b' → index 1, and so on up to 'z' → index 25. Two strings are anagrams exactly when their count arrays are identical, regardless of character order.

A Python list can't be used as a dict key because it's mutable and unhashable, so the count array is converted to a tuple first — tuples are immutable and hashable, making them safe hash-map keys.

results is a defaultdict(list) specifically so the first time a new signature shows up, results[key] doesn't raise a KeyError — it just returns a fresh empty list ready for .append().

By the end of the single pass over strs, every bucket in results holds one full group of anagrams, and list(results.values()) hands them all back without needing to track group order.

Optimal solution

Data structure: Hash Map (Python defaultdict(list)) keyed by a 26-length character-count tuple

  1. Create results as a defaultdict(list) so a brand-new key automatically starts with an empty list.
  2. For each string s in strs, build a 26-length count array (one slot per lowercase letter) and increment count[ord(c) - ord('a')] for every character c in s.
  3. Convert count to a tuple (lists aren't hashable, so they can't be dict keys) and use it as key.
  4. Append s to results[key] — every anagram of s produces the exact same count tuple, so they all land in the same bucket.
  5. Return list(results.values()) — the grouped anagrams, in any order.
O(n · k) — n strings, each of average length kTime
O(n · k)Space

Code

class Solution:
    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        results = defaultdict(list)

        for s in strs:
            count = [0] * 26

            for c in s:
                count[ord(c)-ord('a')] += 1
                
            key = tuple(count)
            results[key].append(s)
        
        return list(results.values())

Other ways to solve it

Sorted-string key

Instead of a 26-length count tuple, use ''.join(sorted(s)) as the key — two strings are anagrams exactly when their sorted characters match. Simpler to write and explain under pressure, but sorting each string costs O(k log k) instead of O(k), so it's a good fallback if you blank on the counting-array trick, not the first choice for large inputs.

class Solution:
    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        results = defaultdict(list)
        for s in strs:
            key = ''.join(sorted(s))
            results[key].append(s)
        return list(results.values())
O(n · k log k)Time
O(n · k)Space

Brute-force pairwise comparison

Compare each string against one representative of every existing group using Counter equality (or sorted-string equality) and place it in the first matching group, else start a new one. No hashing trick needed — easy to reason about out loud — but it's O(n² · k) in the worst case, so only mention it as the naive baseline you're improving on.

class Solution:
    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        groups = []
        for s in strs:
            placed = False
            for group in groups:
                if Counter(group[0]) == Counter(s):
                    group.append(s)
                    placed = True
                    break
            if not placed:
                groups.append([s])
        return groups
O(n² · k)Time
O(n · k)Space

Tips to remember this pattern

Mental shortcut — “Same letters, same counts → same bucket.”

"I'm turning each string into a canonical count-based fingerprint and bucketing by it in a hash map — that's a single O(n·k) pass instead of comparing every pair of strings, and the 26-slot count array keeps each fingerprint a fixed, hashable size regardless of the string's length."

Edge cases to consider

  • Empty input list → return an empty list, no groups
  • A string that's empty "" → its count array is all zeros; every other empty string groups with it
  • A single-character or single-element input → forms its own group of one
  • All strings are anagrams of each other → one big group
  • No two strings are anagrams → n groups of one, same as the input count
  • Input is lowercase-only per constraints — mixed case or non-letter characters would need normalizing (e.g. lowercasing) before counting
